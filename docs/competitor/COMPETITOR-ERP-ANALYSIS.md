# 竞品 ERP 页面结构全解析 + 自有 WebUI 复刻方案（功能优先）

> 2026-08-16 调研。数据来源：① 两家竞品 SPA 前端源码逐页反编译（路由/菜单/表单字段级）② 用户 Chrome 已登录账号实时 CDP 探索 ③ 官网/教程/B站/评测交叉验证。
> 竞品：**上品帮**（shopbang.cn/erp，Web ERP 形态）与 **毛子ERP**（ozon.maozierp.com，插件+后台形态）。
> 目标：为自有 WebUI（worker 管线前端）规划「功能优先」的复刻路径。

---

## 一、竞品定位差异（先看格局）

| 维度 | 上品帮（shopbang.cn） | 毛子ERP（maozierp.com） |
|---|---|---|
| **形态** | 纯 Web ERP（浏览器插件辅助采集） | 浏览器插件为主 + Web 后台（数据/订单/工具） |
| **UI 风格** | 现代 SaaS 简洁风（左侧导航 + 内容区） | 紫色系，Vben Admin 框架（Vue3） |
| **平台** | OZON + WB 双平台 | OZON 为主（WB 有独立后台） |
| **核心卖点** | 店群管理、批量搬家、自动上下架、模板化上架 | 插件一键跟卖、DeepSeek AI 上品、AI 套图、选品规则 |
| **数据能力** | 选品广场（大盘/类目/热销/热词/标签反查） | 榜单选品（5 个 Tab 21 列指标）、类目分析 |
| **商业化** | VIP 会员 + 帮豆（上架消耗/可释放）+ AI 积分 | VIP 会员 + 毛豆（AI 生图/翻译消耗） |
| **后端** | 单店铺授权 Client ID/API Key | 多店铺授权 + Cookie 状态 + 商品限额 |

**结论**：两者核心功能高度重合（上架/订单/选品/定价/店铺），差异在上品帮偏「店群批量运营」，毛子偏「AI 智能化 + 插件体验」。自有 WebUI 复刻应取两者精华，按「上架主链路 → 店铺 → 订单 → 选品 → 定价 → 内容 → 自动化」功能优先排序。

### 关键页面功能要点

**商品刊登·采集箱**
- 浏览器插件采集（OZON/WB/1688/淘宝/拼多多/京东/亚马逊/速卖通/TEMU）→ 批量导入采集箱 → 勾选批量上架
- 手动上架：导出表格模板（按货币分店铺）→ 填表 → 导入 → 校验上架
- 批量导出 OZON 商品数据及销量数据

**上架记录**（13 列）
- 列：商品信息/平台店铺账号/上架状态/库存状态/最低价状态/售价/划线价/货源信息/竞品代码/上架方式/操作时间/上架时间/操作
- 状态机：上架中→上架待校验→上架完成/上架异常；库存：等待→添加中→成功
- 操作：**批量搬家**（需竞品代码、同平台）、异常重上、异常编辑、释放帮豆、批量删除、导出模板、密码查看、校验
- 上架方式：一键上架（自动化）/编辑上架/手动上架/搬家/下架重上

**上架配置**（上架策略模板，多店铺可不同）
- 基础信息：配置名称/平台/备注
- 通用属性：改后售价（原售价或基准价百分比）、改后划线价（须>售价）、最低价（≥售价50%）、货号前缀、品牌（保留当前/无品牌）、图片顺序（不处理/主图不变其余打乱/全部打乱）、图片水印、**防侵权**（过滤品牌信息/删视频图文/颜色样本/AI 修改标题描述降低复制禁令）
- 店铺仓库库存（可多店铺差异化）
- AI 积分消耗 = sku数 × 店铺数

**定时任务管理**
- 按间隔方式（每 N 分钟上架 1 个）/ 分段方式（N 个商品在时段内均时发布）
- 状态：待开始/处理中/已完成/已中断/已取消（任务保留 15 天）

**OZON线上商品**
- 列：商品信息/货号/售价/划线价/最低价/库存/重量/尺寸/类目/店铺/仓库/创建时间/状态（销售中/等待库存/已下架/已归档）
- 操作：同步商品、编辑、批量改库存/改价、归档（自动/手动）、修复图片（图片丢失）、批量搬家（相同类目→WB）、水印
- **价格指数**（Ozon 官方）：有利（推广力度高 7.5%）/中等（5%）/不利；达标：>50% 有指数、>80% 有利、<10% 不利

**我的订单**
- 列：货号/平台单号/采购单号/国际物流单号/物流商/仓库/SKU/商品名称/数量/订单价格/采购成本/利润/买家ID/下单时间/备注/货源地址/货源备注/采购快递/采购平台
- 状态：等待备货→等待发运→已准备发运→运输中→已签收/已取消（取消原因：发货后取消/买家没取货/对交货时间不满意）
- 操作：批量备货（确认后不可拆分）、打印面单+拣货单、导出当前条件订单、批量采购、颜色标签标记、同步订单（60 天）、物流查询（国际/尾程）
- 买家黑名单：刷单/频繁退货退款/疑似信用诈骗/拍下不付款/货到付款拒收/恶意差评/恶意威胁/偏远地区

**OZON店铺分析**（Analytics 指标集）
- 订购商品数量/订购金额/唯一身份访问者/商品卡访问/搜索和目录展示次数/从卡片到购物车转化率/搜索目录加购率/已取消/已退回/详细指标 + 总计平均值 + 切换账号/店铺

**跨境定价（OZON定价器）**
- 输入：商品类目（可 SKU/链接识别）、采购成本、重量(g)、包装尺寸（超体积计抛）、物流商、划线价折扣
- 其他：广告费比例（搜索+展示）
- 输出：物流费（到取货点）、毛利/毛利率、商品成本、平台费用（Ozon 代理费 2%≥15≤200 卢布 + 佣金）、广告投入
- 物流类型：超级轻小件/低客单轻小件/轻小件/大件/高客单轻小件/高客单大件；方式：邮政/空运/陆空/陆运，到取货点/配送上门

**商品编辑页（editGoods）** — 7 大分区：
1. **店铺和仓库**：上架店铺、上架配置
2. **类目和属性**：产品类目、产品属性（20 个字段：型号名称/简介/#主题标签/JSON富内容/需要标记代码/原厂包装数量/统一计量单位商品数量/材料/原产国/欧亚经济联盟HS编码/组合成类似产品/条形码(FBP)/…）
3. **描述信息**：标题（俄文、推荐格式）、AI 一键生成标题/简介/标签（消耗积分）
4. **变体信息**：变体表格（图片/视频/货号一键生成/售价/划线价/最低价/商品颜色/件数，最多 80 变体，同首行批量填）
5. **包装信息**：包装重量(g)、长宽高(mm)
6. **货源和备注**：货源地址、货源备注、竞品代码
7. **采集图片**：采集图/本地/网络，最多 30 张；批量水印/批量翻译/批量删除；图片顺序控制；AI 商品套图（每张消耗积分）
- 附加：上架模式（手动上架/编辑上架）、货号生成设置（自定义前缀/随机数/单品方式/分段方式）、防侵权开关、JSON 富内容编辑器（图片/视频/列表/表格/左右图文板块）、保存为模板、立即上架/定时上架、AI 填写产品信息、自动颜色样本

### 关键功能要点

**在线商品**
- 列：商品信息/类目佣金/状态/价格/库存/重量/货源信息/创建日期 + 找货源
- tab：所有/销售中/准备出售/错误；操作：同步所选/同步所有、开启自动同步、批量改价/改库存/改重量/参加促销/归档/重上
- 状态含「错误」类（下架/审核失败），可批量重上
- 价格指数（有利/中等/不利）

**采集箱**
- 全平台采集（1688/淘宝/天猫/京东/拼多多/OZON/WB/速卖通/亚马逊）+ **手动创建商品** + **1688 快速选品采集**
- 列：图片/产品名称/采集价格/sku数量/采集来源/备注/创建时间/更新时间/操作（AI 编辑/上架）
- 批量删除/清空采集箱；上限 1000 条（会员）

**AI编辑 / 手动创建商品**（/product/ai/edit）
- 主要信息：上架店铺/产品类目（**AI 自动匹配类目**）/标题（**DeepSeek AI 生成** + AI 翻译 中文⇄俄文）/品牌（无品牌）/包装重量(g)/包装尺寸(mm)/型号名称/#主题标签/条形码/简介/JSON富内容/**货源地址/货源备注**/制造商/制造国
- 变体表格：SKU名称/图片/视频封面/视频/标题/包装重量/包装尺寸/主题标签/简介/型号名称/货号/**采购价**/售价/划线价/一个产品中的单位
- 支持 Ozon 官方属性 schema 全字段（含「填写更多属性」展开）
- 按钮：一键生成标题/#主题标签/描述（DeepSeek）、**AI套图生成**、保存草稿、上架至OZON、删除草稿

**一键上架配置**（浏览器插件，抖音/B站教程确认）
- 店铺选择（多店铺勾选，货币须一致）、品牌（复制当前/无品牌）、图片顺序（不处理/随机打乱/主图不变其余打乱）、上架方式（**防侵权跟卖 hand / 强制跟卖 api**）、水印、合并变体、浮动价格、货币（¥/₽/$/€/Br/₸）、货源价格/链接/备注、货号一键生成、原售价（黑标价自动抓取）、售价批量倍率（如 0.95 折）、划线价（默认 2 倍）、商家方式提示（强制跟卖有下架风险）

**选品规则**（插件，筛选条件自动收藏批量上架）
- 规则名称/标签名称/优先级/卡片背景颜色/是否自动收藏 + 30 个条件：品牌（无/有/全部）、评分、月销量、月销售额、价格、重量、上架时间、月周转动态、广告费占比、参与促销天数/折扣/转化率、付费推广天数、商品卡浏览量/加购率、搜索目录浏览量/加购率、展示转化率、发货模式、退货取消率、跟卖人数、跟卖最低价
- 符合条件的 Ozon 前台商品卡片自动打标签 + 变色 → 一键批量上架

**榜单选品**（5 Tab × 21 列）
- Tab：热销商品/热销新品/潜力商品/蓝海商品/中国专区
- 列：商品信息/所属类目/月销量/月销售额/单价/月销售额环比/月浏览量/日均销量/日均销售额/点击率/商品卡加购率/搜索和目录加购率/转化率/发货模式/交货时间/体积/重量/可用性/可跟卖？/创建日期
- 操作：批量上架/找货源/一键上架；筛选：商品名/SKU/日期/类目

**我的订单**
- 7 状态 tab：所有/等待备货/等待发运/运输中/有争议的/已签收/已取消
- 列：标记/货件编号/所属店铺/状态/商品信息/订单金额/费用/利润/买家信息/仓库与配送方式/追踪号码/取消方+原因/下单+更新时间/操作
- 操作：取消货件（选原因）、打印、编辑颜色标签、保存货源信息（货源地址/价格/备注）、采购信息（采购单号/采购快递/单号）、买家标记

**定价工具 / 利润计算器**
- 定价工具：类目佣金（下拉选）+ 采购成本 + 重量 + 尺寸 + 期望利润率% + 物流商（GUOO 等）+ 国内运费+代贴单 + 广告费 → 售价(¥)+≈₽ + 划线价 + 毛利明细（采购成本/平台佣金/跨境物流费(不计抛)/国内运费+代贴单/广告费）
- 利润计算器：反推模式（输入售价 → 利润/利润率）
- 汇率实时（¥1 = ₽12.5 左右），双币显示

**店铺列表**
- 列：店铺名称/Client ID/密钥过期时间/平台/商品限额/货币类型/默认店铺/仓库数量/备注/Cookie状态/状态/绑定水印/添加时间

### 与竞品的差距 → 复刻优先级（P0 先做，P3 后做）

**P0（核心上架链路，最优先）**
1. **上架配置模板**（对标上品帮 `/upGoodsSetting`）——上架策略模板化：改后售价/划线价/最低价、货号前缀、品牌、图片顺序、水印、防侵权开关；多店铺可不同配置。这是「批量上架」的前提，Worker 管线已有等价参数（extensions），缺的是 WebUI 配置层。
2. **上架记录页增强**（对标 `/batchRecord`）——当前 /tasks 只有进度，需补：上架方式筛选、状态机（上架中/异常/完成 + 库存/最低价状态）、批量操作（异常重上、批量重传、导出）、竞品代码、货源信息展示。
3. **采集箱批量上架**（对标 goodsCollect）——多选采集箱草稿 → 选店铺/上架配置 → 批量提交。Worker 已有 submit_draft 批量能力，缺前端批量入口。
4. **订单列表 + 采购/货源信息**（对标 orderManage）——Worker 已有 ozon_order 数据能力（未接线 WebUI），补：订单状态 tab、批量备货标记、货源/采购信息、利润列、导出。

**P1（店群运营）**
5. **多店铺差异化配置**（上品帮核心）——同一商品对不同店铺设不同价格/库存/货号前缀；店铺分组。
6. **商品搬家 / 下架重上**（Reup）——在售商品 → 新店铺/平台重上；Ozon 下架商品一键重上（Worker 全量重传天然支持）。
7. **自动上下架 / 定时任务**（orderTimingList）——间隔/分段定时批量上架。
8. **在线商品批量操作**——批量改价/库存/归档/修复图片 + 价格指数展示。

**P2（数据/AI/自动化）**
9. **榜单选品数据页**（对标毛子 5 Tab）——Worker 已有 discover/what_to_sell 数据通道（蓝海评分/热销），缺数据看板 UI；先做「已采集榜单 + 一键入采集箱」。
10. **定价工具内嵌**（Worker 已有 estimate 端点 + 定价公式）——补类目佣金/物流/广告费输入 → 售价+利润明细双币显示，并联动上架。
11. **消息/催评自动化**（autoMsg）——消息模板 + 发送记录（Ozon API 支持）。
12. **AI 套图扩展**（已有 ImageStudio）——补齐白底/场景/卖点/其他 4 类型 + 批量重绘/翻译 + 生图记录。

**P3（管理/商业化）**
13. 子账号/团队权限、设备管理、买家黑名单、数据大屏（复用 /datascreen 形态）、VIP/计费体系（帮豆/毛豆类比 → 积分）。

### 复刻的架构原则

- **页面形态学上品帮**（左侧导航分组 + 顶部店铺切换 + 内容区表格）——Vben/Element 风格，与我们现有 React 组件体系兼容。
- **智能化学毛子**（AI 编辑/套图/选品规则）——复用现有 mxou deepseek-v4-flash 管线 + ImageStudio。
- **Worker 不动或最小动**：竞品功能 80% 是「Worker 已有能力 + WebUI 接线 + 配置层」；真正需要 Worker 新增的只有：订单数据 API（若未接线）、自动上下架调度（若未接线）、消息模板 API。
- **功能优先排序依据**：按「批量上架效率」主线排 P0（上架配置→上架记录→批量采集→订单），因为这是两类竞品共同的第一卖点，也是用户最痛的环节。
